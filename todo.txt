[MarginCall_2X 系統重生藍圖：從「腳本」進化為「數位交易員」]

================================================================================
【PHASE 0: 基礎工程與環境標準化 (Infrastructure)】
================================================================================
1. [ENV] 移除 venv.zip
   - 改用 `uv` (極速包管理) 或 `poetry` 管理依賴。
   - 建立標準 `pyproject.toml`，鎖定版本（避免 yfinance 或 shioaji 改版導致崩潰）。
2. [CONFIG] 環境變數安全化
   - 建立 `.env.example` 模板。
   - 使用 `pydantic-settings` 讀取配置，對 API Key 進行強型別驗證。
   - 區分 `DEVELOPMENT` 與 `PRODUCTION` 模式。
3. [LOG] 結構化日誌
   - 引入 `Loguru`，將日誌分為 INFO (操作) 與 ERROR (警報)。
   - 實作「交易上下文追蹤」(Trace ID)，追蹤每一筆從 Telegram 指令到成交的完整流程。

================================================================================
【PHASE 1: 核心架構大重構 (Architectural Decoupling)】
================================================================================
1. [AGENT] 建立 Agent 核心類 (src/agent.py)
   - 邏輯解耦：將 AI 的「思考、推理、模型切換」從 Telegram 邏輯中抽離。
   - 故障轉移 (Failover)：實作 Gemini 2.0/1.5/Flash 的自動降級與斷路器模式 (Circuit Breaker)。
   - 上下文窗口管理：自動清理舊的對話歷史，避免 Context Overflow。
2. [UI] Telegram Bot 模組化 (src/bot.py)
   - 僅負責「訊息收發」與「格式化顯示」(MarkdownV2)。
   - 將 /trade, /analyze, /vturn 分解為獨立的 Handler。
3. [TOOLS] 工具自動註冊系統 (src/tools.py)
   - 使用 `@tool` 裝飾器自動將 `engine_*.py` 中的函數註冊到 AI 工具箱。
   - 實作「乾跑模式」(Dry Run)：AI 可以先預演操作，由用戶確認後才執行。
4. [DATA] 數據庫抽象層 (src/database.py)
   - 引入 `SQLAlchemy` 或 `Tortoise-ORM` 取代直接操作 SQLite。
   - 使用 `Alembic` 進行數據庫 Migration (版本控制)。

================================================================================
【PHASE 2: 肌肉強化：金融引擎升級 (Engine Hardening)】
================================================================================
1. [BROKER] Fubon (Shioaji) 穩定性改造
   - 實作「自動重連機制」：監控 Socket 狀態，斷線時秒級重啟。
   - 非同步回報系統：成交回報與行情推送使用 `asyncio` 隊列處理，避免阻塞 AI 思考。
2. [RISK] 壓力測試引擎 (engine_risk.py)
   - 增加「保證金預警模擬」：若大盤大跌 5%，模擬當前持倉的保證金佔用率。
   - V-Turn 偵測優化：結合 CVD (成交量 Delta) 與 RSI 背離進行三重確認。
3. [PORTFOLIO] 倉位管理自動化
   - 實作「自動止盈止損 (TPSL)」掛單邏輯。
   - 增加「稅務與手續費計算」：精確計算台股 0.3% 交易稅對損益的影響。

================================================================================
【PHASE 3: AI 認知與自省系統 (Cognitive Intelligence)】
================================================================================
1. [MEMORY] 額葉記憶系統 (Frontal Lobe)
   - 仿照 OpenAlice，在每次對話開始前讀取 `brain_state.md`。
   - 讓 AI 記得自己對某支股票的「中長期觀點」，不被短期波動帶偏。
2. [NLP] 深度情報收割機 (nlp_worker.py)
   - 升級為獨立後台服務，支持異步抓取 SEC Filings、台股法說會全文。
   - 情感評分機制：對新聞進行 -1.0 到 1.0 的量化評分，直接供 Risk Engine 調用。
3. [GIT-LOG] 交易決策日誌
   - 每一筆交易必須附帶「Decision Message」（為什麼買？預計持有多久？止損點在哪？）。
   - 提供 `/history <symbol>` 指令，讓 AI 回顧過去對該股票判斷的準確率。

================================================================================
【PHASE 4: 監控、可視化與自動化任務 (Observability)】
================================================================================
1. [DASHBOARD] 戰情室 Web UI
   - 使用 `Streamlit` 建立本地網頁，即時顯示：資產曲線、保證金溫度計、AI 情緒值。
2. [SCHEDULER] 進階任務調度
   - 使用 `APScheduler`：開盤前 15 分鐘自動抓取 ADR 與夜盤表現。
   - 盤後 1 小時自動生成「今日戰報」與「錯誤總結」。
3. [HEALTH] 系統自我修復
   - 監控 API 額度 (Gemini API Usage)。
   - 當網路中斷或 API 失效時，透過 Telegram 發送「靜默模式」警告。
